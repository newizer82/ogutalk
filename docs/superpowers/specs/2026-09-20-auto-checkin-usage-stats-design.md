# 자동 활동 기록 (UsageStats 기반 체크인) — 설계서

> 작성일: 2026-09-20
> 상태: 승인됨 (구현 계획 수립 전)
> 관련 브랜치: `spike/usage-stats` (기술 검증용, 폐기 예정)

---

## 1. 배경

오구톡의 매시 59분 알람 팝업은 사용자에게 지금 무엇을 하고 있었는지 4개 버튼
(🎯목표할일 / 📚공부업무 / 📱SNS유튜브 / 😴휴식식사) 중 하나로 기록하게 한다.
이 체크인 기록이 리포트 탭과 주간 리포트의 유일한 데이터 원천이다.

**문제**: 매시간 1탭을 요구하는 구조가 실사용에서 작동하지 않는다. 개발자 본인이
사용 중에도 체크인을 누르지 못해 알림 배지가 10개 이상 쌓인다. 체크인이 비면
리포트도 비고, 앱의 유일한 고유 데이터가 사라진다.

**검토한 대안과 탈락 사유**:

| 방법 | 탈락 사유 |
|---|---|
| 알림 액션 버튼으로 마찰 감소 | 여전히 매시간 주의를 요구 — 배지 누적 문제 그대로 |
| 놓친 시간 몰아서 회고 입력 | 기억 기반이라 부정확하고, 채우는 것 자체가 숙제 |
| 체크인 빈도 축소 (하루 3~4회) | "매시 59분" 정체성과 분리되고 데이터가 성겨짐 |
| 게이미피케이션 (연속일수·보상) | 이미 지친 사용자에게 부담을 추가할 뿐 |
| 화면 ON 시간만 측정 (무권한) | 상시 포그라운드 서비스(영구 알림) 필요 — 권한 부담은 비슷한데 데이터는 빈약 |
| 접근성 서비스 | Play 정책상 선언 양식 대상이며 접근성 외 목적 사용에 제재 리스크 |

**채택**: Android `UsageStatsManager`로 앱별 포그라운드 시간을 읽어 활동을 자동
판정한다. 사용자 탭 0번.

## 2. 기술 검증 결과 (완료)

`spike/usage-stats` 브랜치에서 실기기(삼성 SM-S936N / One UI) 검증 완료.

- 앱별 포그라운드 시간 조회 정상 동작 (이벤트 611~697개 스캔)
- 권한 흐름 정상: 설정 → 사용정보 접근 허용 → 앱이 즉시 인식
- 앱 이름이 한글로 정상 표시 (`설정`, `카카오톡`, `삼성 월렛`, `One UI 홈`)
- 3시간 조회 시 총합 약 23분 — 화면 꺼짐 구간이 특정 앱에 잘못 누적되지 않음
- 60분 조회와 3시간 조회에서 동일 세션의 수치가 일치

검증 중 발견·수정한 버그 3건은 본 구현에 반드시 반영한다.

1. **조회창 전체를 덮는 연속 세션 누락** — 창 안에 이벤트가 없어 0초로 집계됨.
   → 조회창보다 앞(12시간)부터 스캔하고 각 구간을 `[begin, end]`로 잘라 누적.
2. **화면 꺼짐 시 시간 폭증** — PAUSED 없이 끝난 세션이 무한 누적됨.
   → `SCREEN_NON_INTERACTIVE`(16) / `KEYGUARD_SHOWN`(17) / `DEVICE_SHUTDOWN`(26)에서 세션 종료.
3. **자기 패키지 스킵으로 직전 앱 시간 부풀림** — 오구톡 이벤트를 스캔에서 건너뛰어
   이전 앱 세션이 닫히지 않음. → 스캔은 전부 하고 출력 시에만 제외.

**미검증 항목**: 60분을 넘는 단일 연속 세션(버그 1의 직접 검증), 삼성 외 제조사.

## 3. 목표 / 비목표

**목표**
- 사용자 조작 없이 시간대별 활동 기록이 쌓인다.
- 알람 팝업이 "지난 1시간에 무엇을 했는지"를 보여준다.
- 기존 리포트 탭·주간 리포트가 수정 없이 그대로 동작한다.
- 권한을 허용하지 않은 사용자도 앱이 지금과 동일하게 작동한다.

**비목표 (이번 범위 밖)**
- 사용시간 데이터의 서버 전송 — 기기 내 처리만 한다.
- AI 코칭·개인화 리포트.
- 임계치 기반 실시간 개입 알림 ("유튜브 30분 넘음").
- 리포트 탭에 앱별 사용시간 차트 추가 (OS 디지털 웰빙과 중복).
- iOS 지원 (해당 API 없음).

## 4. 핵심 설계: 소급 기록(backfill)

### 4.1 제약

알람이 울리는 순간에 JS가 항상 실행되는 것은 아니다. 앱이 종료된 상태면
네이티브 알림만 표시되고 웹뷰 코드는 돌지 않는다. 따라서 "알람 시점에 기록"은
성립하지 않는다.

`UsageStatsManager`는 **과거 구간을 조회할 수 있다.** 이 성질을 이용해 나중에
채워 넣는다.

### 4.2 알고리즘

트리거 시점(앱 포그라운드 진입, 또는 앱이 살아있을 때 알람 수신):

```
1. lastBackfillAt(로컬 저장) ~ 현재 를 정각 기준 1시간 슬롯으로 분할
   - 최대 24시간까지만 소급 (그 이상은 버림)
2. 각 슬롯마다:
   a. 이미 해당 슬롯에 체크인 기록이 있으면 건너뜀 (멱등)
   b. UsageStats로 그 슬롯의 앱별 포그라운드 시간 조회
   c. 슬롯 총 사용시간이 5분 미만이면 건너뜀 (취침·미사용 구간)
   d. 가장 오래 사용한 앱을 선정
   e. 앱 → 카테고리 매핑 (4-4 참조)
      - 매핑되면: 체크인 1건 저장 (슬롯 종료 시각으로 기록)
      - 매핑 안 되면: 저장하지 않음. 미분류 앱으로만 기억
3. lastBackfillAt = 현재
```

슬롯은 정각 기준(예: 14:00~14:59)으로 정의한다. 기존 체크인 리포트가 시간대별
집계(`hourCount`)를 하므로 정각 정렬이 자연스럽다.

### 4.2.1 알람 시점과의 관계

알람은 매시 **59분**, 즉 슬롯이 끝나는 시점에 울린다. 이때 앱이 살아 있으면
팝업은 **막 끝나가는 현재 슬롯**(예: 15:00~15:59)을 즉시 조회해 표시하고 그 자리에서
기록한다. 앱이 꺼져 있어 이 경로를 타지 못한 슬롯은 나중에 소급 기록이 채운다.
두 경로 모두 같은 멱등 규칙(4.2-2a)을 거치므로 중복 기록은 발생하지 않는다.

### 4.3 왜 이 방식인가

- 사용자가 앱을 열지 않아도 데이터가 유실되지 않는다 (다음에 열 때 채워진다).
- 원시 사용시간을 저장할 필요가 없다 — 필요할 때 OS에서 다시 읽으면 된다.
- 기존 체크인 저장소·리포트 코드를 그대로 재사용한다.

## 5. 저장

| 데이터 | 위치 | 비고 |
|---|---|---|
| 체크인 기록 | 기존 그대로 — 비로그인 `ogu_local_checkins`, 로그인 `notification_log`(`notification_type='checkin'`) | 스키마 변경 없음 |
| 자동 기록 ON/OFF | `ogu_settings`의 `autoCheckin` (기본 `false`) | 스칼라 설정이라 기존 통합 설정 객체에 추가 |
| 앱→카테고리 사용자 수정 | 신규 로컬 키 `ogu_app_category` | 엔티티성 맵이라 `ogu_settings`와 분리 (기존 규칙 준수) |
| 마지막 소급 처리 시각 | `ogu_settings`의 `lastBackfillAt` | |
| **원시 앱 사용시간** | **저장하지 않음** | 프라이버시·용량 이득, 정책 부담 감소 |

**기존 체크인 레코드 형식을 그대로 쓴다** (`activity_type`, `alarm_hour`, `created_at`).
자동/수동 구분 필드는 두지 않는다 — 리포트가 `activity_type`과 `alarm_hour`만
집계하므로 소비처가 없고, `notification_log`에는 자유 형식 컬럼이 없어 추가하려면
스키마 마이그레이션이 필요하기 때문이다.

**주의**: 기존 `saveCheckin()`은 `alarm_hour`와 `created_at`을 **호출 시점의 현재
시각**으로 채운다. 소급 기록은 반드시 **해당 슬롯의 시각**으로 채워야 하므로,
시각을 인자로 받을 수 있도록 저장 함수를 확장한다(기존 호출부는 기본값으로 동일 동작).

## 6. 앱 → 카테고리 매핑

### 6.1 내장 매핑

패키지명 기준 소규모 테이블을 `src/data/appCategories.js`에 둔다.

- `sns` (📱 SNS/유튜브): 유튜브, 인스타그램, 틱톡, 페이스북, X, 넷플릭스, 트위치
- `study` (📚 공부/업무): 노션, 구글 드라이브/문서, 슬랙, 팀즈, 메일, 캘린더, 오피스
- `rest` (😴 휴식/식사): 갤러리, 음악 앱, 배달 앱, 쇼핑 앱, 지도/내비

`goal_work`(🎯 목표 할일)는 앱만으로 판정할 수 없으므로 자동 매핑 대상에서 제외한다.
사용자가 직접 지정한 경우에만 부여된다.

### 6.2 미분류 앱 처리

내장 매핑에 없는 앱은 **기록하지 않는다.** 틀린 분류를 지어내면 리포트 신뢰도가
무너지기 때문이다. 대신 알람 팝업에 앱 이름을 그대로 보여주고, 사용자가 원하면
그 자리에서 카테고리를 한 번 지정한다.

### 6.3 수정 학습

사용자가 알람 팝업에서 분류를 바꾸면:
1. `ogu_app_category`에 `패키지명 → 카테고리` 저장
2. 방금 기록된 체크인을 수정된 카테고리로 갱신
3. 이후 해당 앱은 사용자 지정 값을 우선 사용 (내장 매핑보다 우선)

## 7. UI 변경

### 7.1 알람 팝업 (`AlarmPopup.jsx`)

**자동 기록이 켜져 있고 권한이 허용된 경우**

```
⏰ 15:59
지난 1시간 · 📱 유튜브 42분
→ SNS/유튜브 로 기록했어요
[ 다르게 기록 ]
```
아무것도 누르지 않고 닫아도 이미 기록은 끝나 있다(탭 0번).
`다르게 기록`을 누르면 기존 4개 카테고리 버튼이 펼쳐지고, 선택 시 6.3의 수정 학습이 동작한다.

미분류 앱이면 두 번째 줄을 "아직 분류되지 않은 앱이에요"로 바꾸고 카테고리 버튼을 바로 펼친다.

**그 외(권한 미허용 또는 기능 OFF)**: 현재의 수동 4버튼 팝업을 그대로 유지한다.

### 7.2 설정 탭

"⏱️ 자동 활동 기록" 섹션을 신규 컴포넌트로 추가한다. `SettingsPage.jsx`가 이미
524줄이므로 이 섹션은 별도 파일로 분리해 붙인다.

- 토글 (기본 OFF)
- 권한 상태 표시 / 권한 설정 열기 버튼
- 켜기를 누르면 **고지 화면 먼저** (7.3)

### 7.3 사전 고지 (Play 정책 필수 요건)

토글을 켜면 시스템 설정으로 보내기 **전에** 앱 내 고지를 표시하고 명시적 동의를 받는다.

> **오구톡이 앱 사용시간을 읽습니다**
> 매시간 무엇을 했는지 자동으로 기록해 리포트를 채우기 위해 사용합니다.
> 이 정보는 **기기 안에서만 처리되며 서버로 전송되지 않습니다.**
> [ 허용하고 계속 ]  [ 취소 ]

자동 닫힘 팝업이나 수동적 동의는 사용하지 않는다. `허용하고 계속`을 누른 뒤에만
`ACTION_USAGE_ACCESS_SETTINGS`로 이동한다.

## 8. Play 정책 준거 (조사 완료)

공식 문서 확인 결과:

1. **`PACKAGE_USAGE_STATS`는 선언 양식(declaration form) 대상이 아니다.**
   제한된 권한 목록(SMS/통화기록, 백그라운드 위치, 모든 파일 접근,
   `QUERY_ALL_PACKAGES`, 접근성 API, 정확한 알람, 전체화면 인텐트)에 포함되지 않는다.
2. **"민감한 기기 또는 사용 데이터"에 해당하므로 사전 고지·동의가 필요하다.**
   → 7.3으로 충족.
3. **데이터 안전 섹션**: "기기에서 로컬로만 처리되고 외부로 전송되지 않는 데이터는
   공개할 필요가 없다." → 기기 내 처리만 하므로 신고 대상이 아니다.
4. 권한은 "스토어 등록정보에 홍보된 핵심 기능에 필요"해야 한다.
   → **배포 시 스토어 설명에 자동 활동 기록 기능을 명시해야 한다.**

앱 이름 조회는 `QUERY_ALL_PACKAGES`(선언 양식 대상) 대신 `<queries>` 인텐트 필터를
사용해 선언 의무를 피한다.

**별건 확인 필요**: 이미 사용 중인 `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`이
Play Console 선언 양식 대상이다. 프로덕션 게시 중이므로 통과했을 가능성이 높으나
점검이 필요하다. 본 설계 범위 밖.

## 10. 검증

**자체 체크 스크립트 1개** (`node`로 직접 실행, 테스트 프레임워크 도입하지 않음).
순수 함수만 대상으로 한다:

- 슬롯 분할: 임의의 `lastBackfillAt`과 현재 시각에서 올바른 정각 슬롯 목록이 나오는가
- 24시간 상한이 지켜지는가
- 멱등성: 이미 기록된 슬롯을 건너뛰는가
- 5분 미만 슬롯을 건너뛰는가
- 매핑 우선순위: 사용자 지정 > 내장 매핑 > 미분류(기록 안 함)

**실기기 확인**
- 권한 미허용 상태에서 기존 수동 팝업이 그대로 뜨는가
- 권한 허용 후 앱을 몇 시간 뒤 열었을 때 그 사이 슬롯이 채워지는가
- 리포트 탭·주간 리포트가 자동 기록 데이터로 정상 렌더되는가
- 미검증으로 남은 버그 1(60분 초과 연속 세션)을 이 기회에 확인

## 11. 알려진 한계 (의도적 수용)

- 앱을 오래 열지 않으면 그만큼 리포트 반영이 늦다. 24시간을 넘긴 구간은 버려진다.
- 한 슬롯을 하나의 활동으로 단순화한다. 30분 공부 + 30분 유튜브는 더 오래 쓴 쪽으로만 기록된다.
- 앱만으로는 의도를 알 수 없다(업무용 카카오톡 vs 잡담). 수정 학습으로 보완하되 완전하지 않다.
- 1분 미만 짧은 전환은 노이즈로 무시한다.
- 삼성 기기 1대에서만 검증되었다. 다른 제조사에서 이벤트 동작이 다를 수 있다.
- 권한을 허용하지 않는 사용자에게는 기존 문제(체크인 미사용)가 그대로 남는다.
